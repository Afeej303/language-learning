# Implementation decisions
- Use Node 24 with built-in SQLite and browser modules. A single-process college lab can install and test the entire app offline without a package registry or database service.
- Use SQLite WAL and atomic learner-state transactions for durable progress on one host. Language codes partition the question bank and enrolments.
- Provision accounts from the host. Teachers share the MVP administrative role. The authentication adapter owns password verification and opaque sessions so SSO can replace it.
- Each grammar point starts with three worked examples and twelve exercises across four skills. A2 and B1 receive the same pilot coverage so placement and upgrades can run immediately after development approval.
- The sequence starts with decoding and then uses sentence-level vocabulary in context. CEFR mappings are local teaching estimates pending faculty validation.
- Placement interleaves four skills, tests nearest available bands without repeating an item, checks stability at 20 and 24, and stops at 28. Each estimate is capped by the highest correct response in that skill.
- Each skill has its own ordered units. Practice unlocks the checkpoint. A failed checkpoint requires correct review responses on the missed points. B1 completion records B2 as the next study band.
- Limit fuzzy translation grading to one internal edit in one long word. Unlisted paraphrases can be rejected and a spelling tolerance can occasionally change meaning. Faculty can add accepted variants.
- Vocabulary exercises encountered during learning enter a per-student SM-2-style queue. Binary correctness drives ease and intervals. Due times use elapsed days.
- Teacher editing uses labeled fields with syllabus-derived unit and level tags to prevent inconsistent combinations. Weak-point counts increase on errors and decrease on successful retrieval.
- The PWA caches only its public shell. Sign-in, questions and progress require the LAN server. Malayalam and English appear side by side, with independent direction on Arabic stimuli and inputs.
- Three to five items per skill checkpoint keep the pilot runnable. A three-item checkpoint requires three correct answers to reach 80%. Small banks cause overlap between placement, practice and checkpoint.
- Store six CEFR bands as language-independent values. Placement only estimates the three taught bands. B2 marks completion of the supported path, without certifying B2 proficiency.
- Use two nominal/verbal foundation units at A1, relationships and actions at A2, then complex clauses and purpose at B1. This is a compact pilot sequence, with partial A2 marks and mostly unvowelled B1 text.
- Show worked examples from a teacher-editable lesson field. Draft question data and answer keys stay off student endpoints. Vowels are required in an exercise specifically assessing a vowel.
- A teacher edit or withdrawal invalidates an open item's revision. The learner can restart the affected activity while keeping completed placement responses and completed units.
- Use Asia/Kolkata calendar days for streaks. A sign-out invalidates the session on the server, while re-entry resumes the activity.
- Local Chromium launch was blocked by the runner's Unix socket restrictions. Automated HTTP tests cover the student workflow; visual layout and installation on the college tablets still need device verification.
- No live model API credentials were supplied. The draft generator validates the complete batch before committing it. Faculty must review generated language and grading alternatives.
- The build uses English and Malayalam together, including Malayalam instructions on each seeded item. Teacher authoring field labels are principally English.
- The pilot uses a single server process and fully reads the modest question bank during a request. Benchmark and index per-activity queries before a large rollout.
## Future
- College SSO, independently calibrated placement items, larger teacher-reviewed banks and additional languages.
- A one-command localhost demo creates temporary accounts and an approved, disposable database for review. Persistent deployments still start entirely in draft.
- Question explanations are optional bilingual fields on each question. Wrong answers show the accepted answer and any supplied English and Malayalam explanation; generated drafts request both languages.
- Login throttling keys failures by normalized username and client IP, so one user cannot exhaust every account's allowance. Proxy headers are ignored unless an operator explicitly names one with TRUSTED_PROXY_HEADER; only its first address is used.
- Teachers may promote a student's commonly submitted wrong answer into that question's accepted variants. Wrong-answer suggestions are grouped by question and exact raw response so faculty remain in control of grading changes.
- Placement upward movement requires two consecutive correct answers within a skill. A single correct response cannot raise the estimated band; an incorrect response resets the streak. Placement remains a local instructional estimate, not certification.
- Seed banks provide at least twelve distinct Arabic example sentences for each grammar point. A practice set records its question IDs, and checkpoints exclude practiced and previously checkpointed IDs so those assessment items stay disjoint.
- Persist every submitted answer in an append-only attempts table with the learner, item, raw response, correctness, activity context and UTC timestamp so teacher misconception reports can be derived without parsing mutable learner state.
- Normalize common Arabic and Urdu spelling variants symmetrically for grading, including legacy Malayalam chillu spellings to their atomic Unicode characters.
- A question's creator is recorded on teacher or CSV creation. Only another teacher may approve it; every content edit to an approved item returns it to in-review and clears prior approval metadata.
- CSV exports carry IDs and statuses with a UTF-8 BOM. Imports update matching IDs and create other rows as new draft items, preserving moderation for new content.
- Wrong-answer reports show typed responses seen at least three times and cap the list at fifty rows to keep review actionable.
- When a question has no authored feedback, wrong answers use the paired English and Malayalam lesson text for that syllabus point.
- Teacher accuracy reports derive from immutable attempt records for every skill and point; class weakest-topic ranking remains limited to grammar points.
- Choice items keep their full option bank for authors. At serve time one accepted answer and up to four distractors are selected, so learners see at most five options without changing stored content.
- Learner sign-in and reload always land on the home screen. Open activity is resumed explicitly; leaving to home retains the server-side run, and a different run is blocked until that activity is resumed or completed.
- Choice answers use compact responsive tiles: one column on narrow phones, two columns on medium screens, and auto-fit Arabic tiles with a nine-rem minimum. Longer English choices use one column.
- When a checkpoint has consumed all questions kept disjoint from practice, recycle the least recently served approved question for each point. A small bank may have no disjoint checkpoint item after practice; in that case its approved pool is recycled rather than presenting a false approval warning.
- Version the service-worker shell cache with a SHA-256 of its shell assets; a test enforces that every shell change updates the build ID. Shell requests are network-first with offline cache fallback, and updates activate immediately. Defer a client reload while an answer is being edited and reload after submission.
- The Stitch redesign supplies visual direction only: use the cool lavender canvas, forest green primary, amber attention, indigo learning accents and editorial Arabic type while keeping bundled fonts for offline use. Screens render only persisted/API-backed student and teacher data; static prototype metrics, filters and controls are not product behavior.
- Keep the learner path, exercise and teacher workflows on their existing operations. Presentation changes may reorganize DOM into responsive columns, but must not create routes, API calls, progress state or actions that the app does not already support.
